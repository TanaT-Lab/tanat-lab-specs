# tanat-demo - sub-repo spec

> Spec of the **TanaT demos**: narrated, interactive walkthroughs of TanaT
> served as a static site. Status: `tasks/README.md` (board). Task files are
> local working contracts, not versioned: what they teach lands here.

## Purpose / role in the ecosystem

Public showcase of TanaT, primarily for **conference talks**: a player types
real TanaT code step by step, shows its outputs and figures, synchronized with
an audio narration.

## Goal

1. Work with the current TanaT release (0.10.4).
2. Simplify the structure while keeping the existing UX (no redesign).
3. Each demo lasts **less than 5 minutes**.
4. Scale to several demos.

## Scope

- **In scope:** demo content (pipeline code, data, narration, audio), the
  static player and landing page, output generation, CI and Pages deployment.
- **Out of scope:** TanaT features themselves (`tanat`), dataset generation
  (`tanat-synthea`).

## Decisions

| Topic | Decision |
|---|---|
| Content | Aligned on the TanaT MIMIC tutorials (`doc/source/user-guide/tutorials/mimic/`), no extra steps. |
| Single source of code | One `pipeline.py` per demo, split into `# %% <id>` blocks. A generic generator runs it and writes `outputs.json` (code, output, figure per block), the only source read by the player. |
| Staging | `config.js` keeps staging only (metadata, intro, audio, order of stations and block ids). Card metadata (title, subtitle, ...) lives in `demos/<id>/demo.json`; `demos/index.json` is generated and git-ignored. |
| Data | CSV versioned in `data/`, loaded with `pd.read_csv` (no network at a conference). Rebuilt exactly by `data/build_csv.py` (`--check`) from `tanat.dataset.access('mimic4')` (Zenodo 16368465): `hosp/admissions` + one `DEATH` row per recorded date of death. Provenance and licences in `data/README.md`: MIMIC-IV demo (most likely 2.2) under ODbL v1.0; the Zenodo bundle declares CC-BY-4.0 (to reconcile, see open points). |
| TanaT version | Pinned: `tanat==0.10.4` (PyPI), plus `polars<2` until the static-feature join bug is fixed upstream. |
| Audio | Generated by script from `SCRIPT.md` split into sections; local CPU TTS **Kokoro-82M, voice `af_heart`** (RTF ~2.2 on 3 CPUs, no system deps); mp3 versioned, regenerated only when text changes (`tools/tts.py`). |
| Duration | Audio budget about 4 min 20 (currently 5 min 38); build fails above 4 min 45. |
| Palette | `ADMISSION_COLORS` stays a hidden block (not shown on screen): saves time and keeps the demo simple. |
| CI | GitHub Actions + GitHub Pages (replaces `.gitlab-ci.yml`), also run on PRs, TanaT pinned. |
| Tasks | Task files not versioned; board versioned. Reviewed task branches are fast-forward merged into `main` by the orchestrator, no PR for now. |

## TanaT 0.10.4 findings (pipeline)

- Keep whole patients: `pool.which(EntityCriterion(query=pl.Expr))` then
  `pool.subset(ids)`. Not `filter_entities`, which prunes admissions.
- `admission_type` must be Categorical for metrics/clustering, so
  `str.contains` needs `.cast(pl.Utf8)` first.
- `static_data()` is a method; timelines of the 64-patient cohort need
  `allow_large=True`.
- **TanaT bug (root cause found 2026-10-27)**: `store/base/static.py`
  `add_static()` LEFT JOINs the static features on the main index without
  `maintain_order="left"`, drops the id and writes by position. With polars 2
  the order is not kept: labels land on the wrong patients (26/64 right on a
  full pool; on a `subset` view 15/64 right and 23 null). It scrambled the 6a
  facets of the live site until main @ 220e1a7. Workaround: `polars<2` in
  `requirements.txt` (64/64), `pool.subset(ids)` back in step 3a, and
  `tests/test_pipeline_labels.py` guards it (fails on polars 2). Upstream issue
  drafted; drop the pin once fixed.

## Open points

- **Cluster story (decided 2026-10-27, in main).** `normalize=True`,
  `n_clusters=3`. True clusters: 22 patients with a single emergency admission
  (mean 1.4 admissions), 24 with a few stays including deaths (2.9), 18 with
  frequent readmissions (8.5). The narration (TASK-010) must follow.
- Hamming compares a single feature: `admission_type` (decided).
- **Data licence (human).** The Zenodo record "TanaT - MIMIC4 database"
  declares CC-BY-4.0, while the MIMIC-IV demo it contains is ODbL v1.0
  (share-alike for derived databases). The record should probably state ODbL
  and the demo version; its author is on the team.
- `5b` and `3a` outputs include TanaT's progress log (boxes with timings, so
  not reproducible between runs). Consider silencing it for the audience (TASK-010).
- Upstream issue (static features on wrong ids): drafted, to post on `TanaT-Lab/TanaT`.
